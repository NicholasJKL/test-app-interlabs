## Решения

MATCHES_URL возвращает статус 404, поэтому я использовал и подключил mock из примера (data/matches.json).

Решил создать новый пункт фильтра "Идущие" и заносить идущие матчи туда. Отложенные матчи решил оставить в "Предстоящие", потому что по логике им дату должны назначить позже. По идее ещё могут быть отменённые матчи, но в примере их нет, поэтому не обрабатываю. Порядок кнопок фильтра выбран следующим образом: "Все" обычно отображают в начале, затем "Идущие" (так как должна быть самой популярной), затем "Предстоящие" и "Завершённые".

Решил добавить количество идущих матчей в кнопку фильтра "Идущие" для того, чтобы пользователи сразу видели, сколько матчей идут.

## Баги из части 2

1. Звёздочки
     * Неправильная логика функции isFavorite. indexOf() для первого избранного матча возвращает 0, для Boolean - это false. Исправил, поменяв на функцию includes(), которая проверяет наличие id в favorites и возвращает boolean.
     * Функция toggle неправильно использует state (favorites): мутирует массив, не создавая новый. Правильно изменять состояние только через set (setFavorites), передавая новый массив, чтобы происходила перерисовка (React сравнивает старую и новую ссылку и при совпадении пропускает перерисовку). Переименовал toggle в toggleFavorite для удобочитаемости и соответствию наименованиям других элементов.

2. «Обновлено N сек назад»:
     * В useEffect внутри setInterval seconds замыкался на 0, и каждый тик вызывался setSeconds(0 + 1). Создал функцию diffSeconds, которая считает разницу в секундах между текущим временем и временем, когда матч был обновлен. В setSeconds передаю результат этой функции.
     * useEffect не перезапускется. Добавил since в useEffect, чтобы при смене since эффект перезапускался.
     * В useEffect добавил clearInterval(id) для очистки интервала при размонтировании.

## Как я использовал ИИ

Использовал DeepSeek и агент на локальной машине (модель Wrench:9B). Агент писал небольшие функции, а DeepSeek помогал быстрее понимать код и писать большие куски кода.

Весь DeepSeek код проверял на правильность и тестировал самостоятельно. Агент писал совсем небольшие функции, поэтому я сразу на лету проверял на правильность.

Случай: По симптому "все звёзды горят" DeepSeek предположил причину `favorites.length > 0`, но в реальном коде хука было `Boolean(favorites.indexOf(id))` - то есть первый добавленный матч всегда считался не избранным из-за `Boolean(0) === false`. Я заметил по ответу ИИ (он предполагал, а не искал ошибку где-то), что не предоставил код хука, поэтому отправил его в следующем промпте, чтобы у ИИ был точный контекст.
